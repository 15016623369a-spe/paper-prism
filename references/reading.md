# 单篇精读规范

## 输出深度

完整精读应读取全文正文及关键图表，按阅读卡组织；附录只在解释方法、结果或复现必要时读取，标明实际范围。快读保留问题、架构概览、方法、核心结果、创新主张和一项关键局限，不将其伪装成完整精读。只要某一章/公式/图时重点解释该处，并记录未读部分。

## 论文类型适配

| 类型 | 架构重点 | 创新与验证重点 |
|---|---|---|
| 方法/算法/系统 | 输入、表示、模块、目标/损失、训练与推理、输出 | 相对基线变化、消融、效率、适用边界 |
| 实证/实验 | 研究问题、样本、干预/变量、控制、测量、分析 | 发现与研究设计贡献，效应、混杂和外推限制 |
| 理论/数学 | 假设、定义、引理、定理及推导依赖 | 新命题/证明技巧，条件与反例边界 |
| 综述/元分析 | 检索与筛选、分类层次、主题、证据组织 | 新分类或综合，证据覆盖、偏倚、异质性 |

## 两层架构的读法

**章节与论证架构**以原文真实章节为准，记录“这一节讲什么、支撑哪个结论、与前后文如何衔接”。没有方法章节不能补成标准 IMRaD。原文二级小节很多时保留有意义的层级，避免只列通用的引言/方法/结果。

**方法架构**把输入→模块/操作→中间结果→输出串起来，并说明设计动机。给出关键模块的作用、依赖、公式/算法定位、训练和推理区别。若绘制 Mermaid，图表示原文机制或明确标为解释性重构；不要将未证实机制画成定论。理论论文可绘制定理依赖图，综述可给分类树。

## 创新账本

每项创新用同一套字段：

1. 作者的具体主张及原文位置。
2. 比较对象：论文引用的先前方法，或已实际读取的库内/外部相关文献。
3. 改变了哪个问题设定、模块、理论、实验、数据或评价方式。
4. 支撑证据：推导、实验、消融、数据或论证。
5. 分析判断：概念/方法/理论/实证/数据资源/系统/综述综合贡献；实质贡献、增量改进或证据不足必须解释理由。
6. 核查状态：仅复述作者主张 / 原文证据支持 / 已核查所列相关文献 / 待外部核查。

限定“已核查”的范围：比较过 A、B 并不证明全领域首次。时间基准须清楚，是论文发表时的贡献还是截至分析日期的现状。用户未要求评分时不给泛化创新分数、虚构百分比或“顶刊级”评级。

## 结果与批判性阅读

结果记录指标全称/定义、数值、单位、方向、数据划分、样本/数据集、基线与条件；基线提高比例与百分点明确区分。实验结论、作者解释和读者推断各自标识。图表与正文有不一致时逐处定位并说明取值依据。

局限区分作者承认与分析发现，并给出实际证据。关注与当前论文相关的缺失控制、样本代表性、消融、数据泄漏、假设条件、因果与相关性、评价范围，不机械套一份所有学科通用的审稿清单。

综述中提到另一研究的结果只是二手证据；未经读取原研究，不能将其自动登记为已精读论文。
